# TeamSpeak 语音助手设计

频道成员说「团子，播放周杰伦的晴天」，机器人识别唤醒词和指令，让 LLM 选择 `play` 并提取搜索词，再用当前机器人的播放逻辑执行。成员可以用同样的方式说「团子，暂停一下」或「团子，下一首」。机器人在 TeamSpeak 返回实际执行结果。

## 行为与数据流

```text
TeamSpeak 同频道 Opus 音频 → 按说话人解码和分句 → 本地唤醒检测
  → 云端转写唤醒后的指令 → LLM 选择播放动作 → 以说话人身份执行现有命令
```

唤醒词和指令可以连在同一句；单独说唤醒词后，同一位成员可在 4 秒内接着说指令。录音和唤醒状态按机器人实例与说话人隔开。机器人只处理所在频道的成员语音，过滤受管理机器人的音频。说话人离开或机器人换频道、断线时，取消对应的录音和未执行的指令。未唤醒的语音不离开本机。

第一版提供 `play(query)`、`pause()` 和 `next()`。`play` 的 `query` 是非空搜索词，现有播放命令负责搜索与选曲。模型可以不选择动作，例如只听到唤醒词或没有明确的播放指令。模型只收到识别出的指令文字和工具说明；程序从 TeamSpeak 获取说话人身份，并按现有 TS 命令规则授权。

## 模块

[`TS3Client`](../../../src/ts-protocol/client.ts) 发布同频道 Opus 帧，包括说话人的客户端 ID 和昵称。现有 `voiceActivity` 事件继续用于降低播放音量。[`VoiceSession`](../../../src/voice/session.ts) 按说话人解码和分句，用本地关键词模型切出唤醒后的音频。

[`VoiceAssistant`](../../../src/voice/assistant.ts) 将指令音频打包为 WAV，云端转写后把文字传给工具调用模型。[`BotInstance`](../../../src/bot/instance.ts) 使用真实的说话人信息通过现有命令权限判断，调用 `executeCommand` 并回复频道。

## 验收场景

| 场景 | 结果 |
| --- | --- |
| 队列有下一首，成员说「团子，下一首」 | 当前机器人切歌一次，并报告执行结果 |
| 成员说「团子，播放周杰伦的晴天」 | 现有播放命令用提取出的搜索词搜索并播放 |
| 成员只说「下一首」，或者唤醒后没有明确动作 | 播放状态不变；未唤醒的话不提交给 LLM |
| 甲说唤醒词，乙说「下一首」 | 乙的话不会成为甲的指令，也不会触发切歌 |
